## What was rewritten

- **Hardcoded roots:** 336 code string literals that were whole paths into the decompile tree became `str(_REPO)` or `str(_REPO / "<repo-relative path>")`. 307 files gained this two-line header after the docstring and `__future__` imports:
  `_REPO = _pathlib.Path(__file__).resolve().parents[N]  # repository root`
  `N` is 1 for `ida/*.py` and 2 for `ida/jobs/*.py`. `run_job.py` uses `ROOT = str(Path(__file__).resolve().parents[1])`.
- **Paths in docstrings and comments:** 108 decompile-tree paths became repo-relative paths with forward slashes, for example `python ida/run_job.py ...`. A bare root became "the repository root", or `.` when it was quoted. The earlier tree location used in some docstrings was treated the same way. Relative command-line examples such as `ida\jobs\x.py` were already relative and were left unchanged.
- **Scratch paths:** 4 output-directory literals pointed at a local temp/scratch tree. They now read `"local-temp"`. The files are `jobs/i14_probe.py`, `jobs/k9_cat_dump.py`, `jobs/k9_cat_dump2.py` and `jobs/w2_sub_purpose_k1.py`.
- **IDA install path:** the 5 runners now read `IDAT = os.environ.get("IDAT")`. If the variable is unset, `main()` exits with "Set the IDAT environment variable to the full path of idat.exe."
- **Firmware-image reads:** 51 read sites in 42 job scripts now say `sys.exit("The firmware image is not in this repository.")`. The replacement covers the whole `open(<image>, "rb").read()[...]` expression. `import sys` was added to 39 of these files. The files:
  g3_gen_tables, h10_phase, h11_gen_tables, h13_gen_tables, h3_residual_retest, h3_scan_ptr_arrays, h6_gen_tables, h7_gen_tables, h7_jp_labels, h7_main_senders, h8_closure, i12_gen_tables, i17_dataplan, i17_plan, i17_recount, i17_verify, i2_apply_sub_final, i2_h10fix, i2_plan, i2_recount, i5_dump, j10_merge, k10_dump, k5_gen_tables, k7_apply_sub_final3, k7_recount, k7_usbscan, l1_apply_main_final5, l5_apply_typing, l95_window, l96_bytes, l96_cite, l97_cite, l97_scan, l97_tables, m1_apply_main_final6, m5_apply, m6_apply, n1_apply_main_final7, pc_l5_tables, pc_l7_regmatch, w2_8_classify.
- **`find_key.py`:** exits with the firmware-image message just before it reads the updater payload. It can therefore no longer produce key JSON or a decrypted image. `yaesu_cipher.py` holds no key tables. As its docstring says, the tables are read from the updater at run time.
- **Runners: database and image exits.**
  - `run_job.py` exits with "IDA databases are not in this repository." when a `--copy-from` or `--reopen` database is absent, and with the firmware-image message when the `--input` file is absent.
  - `run_open.py` and `run_usb_scan.py` exit with the database message when their database is absent.
  - `run_ida.py` exits with the firmware-image message when the updater is absent. `run_survey.py` does the same for the MAIN and SUB images, and for the DLLs it says the updater files (`Firmware/`) are not in this repository.

  The runners use their own default database and image paths, and none of those are shipped, so they always exit there in this repository. A reader with their own local copies can still run them.
- **Emails:** 0 found. **Identity strings:** 4 were read, all at least 3 characters long, so none was skipped for length. They appeared only inside the scratch paths above and were removed with those paths. **Leftover cloud-sync or per-user temp markers:** 0.

## Deliberate exceptions

- **Radio-internal drive paths are kept.** These are the radio's own SD-card path strings on its drive letter I, such as the FT3D, BACKUP and LMREPAIR folders. They are firmware data, cited next to firmware addresses. They are not paths on any host machine, so rule (e) applies and they were not rewritten. They are in 5 job files: `jobs/stor_fmt.py`, `jobs/stor_sd.py`, `jobs/stor_firm.py`, `jobs/pc_l2_tsv.py` and `jobs/i17_dataplan.py`.
- **Two escape strings were split.** Two string literals ended in a colon followed by a newline escape: the "EXC" header in `jobs/n5_tail.py` and the "byte check failed" message in `jobs/h6_gen_tables.py`. A literal drive-prefix scan read each one as a C or D drive prefix. Each was split into two adjacent literals with the same value, so the scan no longer flags them.

## Things a reader should know

- Many jobs write into `ida/out/<topic>/` and read coverage masks or TSVs from there. Six jobs add `ida/out/main-descent/offline` to `sys.path` to import helpers. Whether those inputs exist depends on what the `ida/out` lane ships.
- IDA job scripts compute `_REPO` from `__file__`. IDAPython sets `__file__` for scripts run with `-S`.
- `decrypted/`, `Firmware/`, `ida/db/` and `ida/log/` are named as bare repo-relative paths in code and docs. None of them is in this repository.
