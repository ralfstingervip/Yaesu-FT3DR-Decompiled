## Binary gate (`.bin`, `.png`, `.pkl`)

30 binaries were checked: 29 `.bin` and 1 `.png`. All 30 passed and were copied.

- **Identity bytes:** none contained an identity string (ASCII or UTF-16LE), an email-shaped string, or any of the host-path markers.
- **Firmware-image hash, size and name:** none matched either firmware SHA-256. None was 4,194,304 bytes, and none matched an `FT3D_*_ver102*.bin` name.
- **Content check:** no candidate had 4 or more 256-byte windows (at least 16 distinct byte values each) found in either decrypted image. Both images were opened read-only.

The kept files are coverage, code, type and residue masks of 505,684 or 1,048,576 bytes, in `l-wave-recon`, `m-wave-recon`, `main-final` .. `main-final7` and `main-unnamed`. Also kept: `ledger-reverify-l/db/dbstate.bin`, a 505,684-byte DB-state mask (not an IDA database), and `irq-knobs/sprite_FFED0A8C.png`.

## Text rewriting

- **Decompile-tree paths:** every absolute path into the decompile tree, in backslash, forward-slash and doubled-backslash forms, was made repo-relative (`ida/out/...`, `docs/...`, `decrypted/...`).
- **Other host paths:** all became `local tree, not in this repo`, or `local-temp` for temp and scratch paths.
- **Firmware strings left as they are:** strings inside the firmware use the radio's own drive letter. Examples are `I:\` and `I:\RECBACKUP` in `link-edges/work/os*.txt` disassembly comments. These are not host paths and were left alone. Drive letters other than C and D are rewritten only when they form a multi-segment path.
- **Firmware strings that were replaced:** one garbled firmware string in `main-full/strings.tsv`, cited again in `main-raw/runs.tsv` at `0x07A360`, contains a drive-D root marker. Under the scan rule that substring was replaced, so that fragment of the cited string is not verbatim.
- **Emails:** none were found in the band.
- **Identity strings:** none survive. 4 identity strings were checked, and none was shorter than 3 characters. Every `owner` in the slice was already in the source, as the ordinary word. None was produced by an identity substitution.
- **Untouched:** firmware addresses, hex bytes and SHA-256 citations.
- **Non-UTF-8 file:** `main-unnamed/work/full_listing.txt` is ASCII with raw `0xFF` firmware bytes in it, so it is not valid UTF-8. It was decoded and re-encoded as Latin-1 so every byte is preserved. It needed no substitutions and is byte-identical to the source. Every other text file is UTF-8, and any BOM it had was kept.

## Python

81 `.py` files were copied, and each one passes `ast.parse`.

- **Repo-relative roots:** 62 files had hardcoded decompile-tree roots, and `sys.path.insert` targets, replaced. Each now uses `_REPO = Path(__file__).resolve().parents[N]`, with N set to the file's depth under the repo root. Scripts that already derived their root from `__file__` were left as they were.
- **Firmware-image exits:** 34 files now stop with `sys.exit("The firmware image is not in this repository.")` at the statement that opened, hashed, or named a `decrypted/FT3D_*_ver102*.bin` image.
- **IDA databases:** no script opens an `.i64` or `.idb`.
- **Scratch-directory defaults:** these are now `local-temp`.

## Final re-scan

After writing, I re-scanned all 529 files in the slice as raw bytes, in both ASCII and UTF-16LE. The scan looked for the identity strings, email shapes, the cloud-sync folder name, the per-user application-data folder name, the agent temp-folder marker, C and D drive roots in both slash styles, and the macOS user-home root. There were 0 hits. No decompile-tree root string remains. **The slice is clean.**
