## Skip reasons

- `.log`: logs are dropped under the sanitise rules. There are 4 in `h8s-decode/work` and 4 IDA decompile logs under `host-usb/*`.
- `.pyc`: compiled Python inside `__pycache__` directories. None was copied, and the slice contains no `__pycache__` directory.
- `not valid UTF-8`: `ida/out/host-usb/inf/inf0.txt`, `inf1.txt` and `inf3.txt`. They are driver INF dumps with an embedded binary PKCS#7 signature blob, so they can't be rewritten as UTF-8 text.

## Binary gate (.bin, .pkl)

All 11 binaries passed all three checks and were copied: the identity and path byte scan (ASCII and UTF-16LE), the firmware hash, size and name check, and the 256-byte window content check against both decrypted images. That makes 5 `.bin` and 6 `.pkl`.
- The five `.bin` files are 505,684-byte per-byte arrays: four IDA decode-size arrays in `h8s-decode/work` and one coverage mask in `inferred-tables/work`. Masks are kept by rule. None has 4 or more firmware-matching windows.
- `fnindex-mid/work/descents.pkl` tripped a first-draft email check that scanned alternating bytes. On inspection that was a false positive from random binary data. The final UTF-16LE check uses interleaved NUL bytes, and the file passes it and every other check.

## Text rewriting

- Every text file was decoded as UTF-8, rewritten in Python, and written back as UTF-8 bytes. PowerShell never handled a file body.
- Decompile-tree paths in every form (both slash styles, doubled backslashes, any case) became repo-relative forward-slash paths. That includes an older short name for the same tree, which appears in two traceback files and one JSON summary. Paths into directories that are not shipped (`decrypted/`, `Firmware/`) were left as bare relative names.
- Other absolute paths became `local tree, not in this repo`, and scratch or temp paths became `local-temp`. The output has 105 of the first placeholder and 6 of the second.
- **Note for the parent:** rule b says any drive letter, so drive-letter strings that are firmware or vendor content, not paths on the owner's machine, were replaced too. These are the radio SD-card folder paths in `c4fm-picture/*`, the Renesas `lowsrc` stdin/stdout/stderr names in `hidden/*` and `fnindex/sub-xref.tsv`, vendor build and PDB paths in `host-usb/*/strings.tsv`, and stray drive-letter-shaped byte sequences in raw string dumps. If those should be restored, the rule needs an exception.
- One email address (an author credit in the GNU `h8300.h` header copied into `h8s-decode/oracle/opcode/`) became `<email removed>`. Assembly operands were left alone.
- No identity string occurred outside a path. Each `owner` in the output is the ordinary English word that was already in the source text.
- 4 identity strings were checked. None was shorter than 3 characters.
- Firmware addresses, hex bytes and SHA-256 citations were not changed.
