## Rewrites applied

- Decompile-tree paths rewritten to repo-relative paths: 32. They occur in `protocols/`, `ptr-arrays/`, `service-window/`, and `sub-frames-sub/req/*.json`. Paths into `decrypted/` keep only their bare relative name, because that directory is not shipped.
- Other absolute paths replaced with `local tree, not in this repo` or `local-temp`: 257 in text, plus 11 temp/scratch pickle paths in Python source.
- Email-shaped strings replaced with `<email removed>`: 36, all in `protocols/sync_sweep.tsv`. These are not real addresses. They are printable-ASCII renderings of raw firmware bytes that happen to match the email pattern. The hex columns next to them are unchanged.
- Identity strings: 4 were loaded (user name, computer name, git name and email). None was shorter than 3 characters, so none was skipped. After the path rewrite, 0 remained in any copied file.
- Python: 29 scripts now take their roots from `Path(__file__).resolve()` (`REPO`) instead of hardcoded roots, across 54 literals. 4 scripts exit with `sys.exit("The firmware image is not in this repository.")` at the point where they would open the decrypted image. These are `port-bit0/n13_rawscan.py`, `port-bit0/n13_verify.py`, `punr-mid/offline/m3_verify.py`, and `rx-tone-dcs/n9_verify.py`. No script opens an IDA database. Many of these scripts import helpers (`common`, `masks`, `rd`, `reach`, `ctx`) from `ida/out/main-descent/offline` and `ida/out/h8s-decode/offline`, which are other lanes. Those helpers load the image themselves.
- Scratch pickles that some scripts read (`descent.pkl`, `reach.pkl`) lived in a temp directory. They were never part of the tree, and the scripts now point at `local-temp`.

## Notes for the parent

1. Band edge: the lane note lists `m-wave-recon` in this band. Under ASCII comparison, `m-wave-recon` sorts before `market-gates` (`-` is 0x2D and `a` is 0x61), so it falls outside `[market-gates, sub-gap)`. I did not write it. It was already present in the destination from another lane.
2. Rule b applies to every drive letter, and I applied it the same way the sibling lanes did. As a result, firmware-internal strings that only look like paths were also masked:
   - the radio's own SD-card volume paths (drive letter I), mostly in `storage/` (`paths.tsv`, `path_owners.tsv`, `string_xrefs.tsv`, `tables.tsv`, `asm/pathbuild.asm`) and also in `menu/`, `pc/`, `sub-final2/`, and `sub-frames-sub/`;
   - the C runtime's stdio device names on drive C;
   - random strings-dump noise in `protocols/*_strings.tsv`.
   This loses SD-card layout detail in `storage/`. The originals are in the decompile tree if the parent decides those firmware strings should be restored.
3. In the strings dumps, a drive-letter-like pattern is left only where a letter or digit comes directly before it. These are byte noise, not paths, and they contain no identity or path marker.
